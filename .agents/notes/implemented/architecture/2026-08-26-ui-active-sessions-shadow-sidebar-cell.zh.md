# Agent Note：遮蔽 single 单元槽位——ui-active-sessions 侧边栏变体

Status: implemented

[English](2026-08-26-ui-active-sessions-shadow-sidebar-cell.md) | 中文

> 范围：`packages/client/ui-active-sessions` 如何在不触碰 `ui-workspace` 的前提下替换侧边栏浏览区；为什么按注册 `priority` 遮蔽单元是整区域变体的规范机制；以及这一取舍有意放弃了哪些能力。本文扩展[槽位系统标准](2026-07-22-slot-type-chain-implementation.zh.md)所定义的组合模型。

## 问题

侧边栏浏览区是一个 single 单元槽（`'sidebar.workspaces'`），由占据它的在位者渲染；`ui-workspace` 拥有它及其添加/重命名/归档能力。产品变体希望同一区域围绕会话活动重组——运行中、等待用户、已完成未读的会话被提升到工作区分组之上的统一区段，且每个区段严格按最近更新排序。分叉 `ui-workspace` 或在其组件中穿入选项，会把第二套呈现模式塞进一个其契约（手动拖拽排序、目录流）恰恰因默认行为已定型而存在的包里。

## 决策

**替换整个区域的变体向同一个已声明槽以更低的 `priority` 注册；槽系统渲染 single 单元的最低优先级在位者，其余在位者继续挂载在其下。**

- `ui-active-sessions` 以 `priority: -1` 注册 `ActiveSessionsBrowser`。`ui-workspace` 保持默认优先级注册不动：仍挂载、仍声明 `sidebar.workspaces.directoryFlow`、仍拥有其 store。移除 `packages/bundle/web-app/cordis.patch.yml` 中变体的组合行——或释放其在位者——无需刷新即还原原版浏览器。
- 排序属于变体契约的一部分，不是选项：各区块由列表快照经纯函数（`src/client/view.ts`）派生并按最近活动排序。原版浏览器持久化的手动账户顺序在此有意不生效；两种呈现是互为替代的产品，而非同一组件的模式。
- 静态注册接受显式的不同 `priority`；同键同优先级抛错。（动态插件包不同：开发态 Guard 会覆写调用方优先级为页面局部排名，这正是本功能的动态原型只能做成自包含替换的原因。）

### 遮蔽有意放弃的能力

变体胜出单元期间，原版浏览器的能力从视野消失，尽管其代码仍在挂载：没有侧边栏添加工作区快捷方式（首屏选择器仍在）、没有重命名/分叉/归档菜单、没有拖拽排序。这些作为该包的 Known Limitations 记录而非掩饰——重新补齐它们意味着要么重复 `directoryFlow` 声明（与挂载中的所有者构成加载期冲突），要么把本包扩成第二个完整浏览器。若变体将来需要这些表面，正确路径是与 `ui-workspace` 协商子槽，而不是从外部伸进其内部。

## 考虑过的备选方案

**对 `ui-workspace` 进行分叉或增加模式开关。** 否决，因为在 `ui-workspace` 内部增加第二种呈现模式会将两种截然不同的产品概念交织在一起，并破坏其已有契约。

**在原生浏览器内协商子插槽。** 延后至需要更细粒度扩展时再行考虑；对于整个区域的重组，采用不同 priority 的 slot shadowing 既能干净地满足需求，又无需修改基础包。

## 后果

- 区域级变体是增量式的，上线或撤回都很廉价；永远不需要与区域所有者协调发版。
- 该模式只适用于整区域替换。更细粒度的组合应走所有者条目声明的子槽，声明所有权保持可强制。
- 两个挂载的浏览器意味着两份区域本地状态；只有胜出者的状态可见，因此落败者不得持有持久副作用。本例两个条目都是共享运行时快照之上的纯呈现器，构造上即满足该规则。
